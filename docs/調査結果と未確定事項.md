## 1. どこから読むか

| 決めたこと | 理由 |
|---|---|
| **all-tools が書き出す集計CSVを読む**(共有の日報データ sqlite3 は読まない) | 集計CSVは all-tools 自身が「グラフと同じ表(残してある集計)」から作っています(`reporting/csv_export.py` の冒頭)。CSVを読めば all-tools の計算をそのまま使えます。共有DBを読むと、集計を作り直す処理をこちらでも持つことになり、式がずれるおそれがあります |
| 置き場所は `<大本>\<ライン>\集計\<yyyy.mm>\<dd>\` | `csv_export.dated_dir` の約束どおりです。大本だけを設定すれば、残りはアプリがたどります |
| 書き込みは一切しない | CSVは開いて読むだけです。ロックは取りません(共有DBも開きません) |

使う3本と列:

| ファイル | 使う列 | 注意 |
|---|---|---|
| `集計_<日>_<ライン>.csv` | 直・合計枚数・合計重量(t)・作業時間合計(分)・稼働時間合計(分)・操業時間(分)・管理ロス設備停止(分)・段取り・突発停止(分)・ハンドリング停止(分)・その他(分)・停止合計(分)・稼働率(%)・生産性(t/h) | 「その他(分)」は v4.44.14 で足された列です。前の版のCSVでは**データなし**として扱います |
| `停止内訳_<日>_<ライン>.csv` | 区分が「直の合計」の行の 分類・記号・内訳・回数・停止時間(分) | 「1件ずつ」の行は合計の内訳なので、足すと二重になります(テスト済み) |
| `集計明細_<日>_<ライン>.csv` | ロット№(ロット数)・梱包数量 梱包単位 包数(包数) | ロット数 = ロット№のある行の数 |

## 2. 計算の決まり(独自に解釈しない)

* 量(枚数・重量・時間・包数・ロット数)は足すだけです。
* **稼働率・生産性は足せない**ので、期間や直をまとめるときは all-tools の式で計算し直します。
  * 稼働率(%) = (1440分 × 日数 − 停止合計) ÷ (1440分 × 日数) × 100
    (**all-tools の集計・グラフ画面「日別稼働率推移」と同じ式**。`summary.period_rows` でその日の全直を足し、
    `ShiftAggregate.operating_rate_pct` = (1440 − 停止合計) ÷ 1440。週・月・年は日数ぶんの1440分で割る = 日別の値の平均。
    直を1つに絞れば集計CSVの「稼働率(%)」と同じ。all-tools と同じく 0 未満でも切り上げない)
  * 生産性(t/h) = 重量(t) ÷ ((1440分 × 直の数 − 停止合計) ÷ 60)
    (`ShiftAggregate.productivity_t_per_h` の分母「稼働時間 = 1440 − 停止合計」を、直の数ぶん足したもの)
  * 直1つ・1日なら、どちらも集計CSVの値と同じになります(テスト済み)。
  * 生産性の分母は直の数ぶんの稼働時間のままです(all-tools に期間の生産性を出す箇所が無いため。下の #2)。
* **欠損と 0 を分けます。** 集計CSVが無い日・空欄はデータなし(グラフでは薄い帯)です。0 と書いてあるものだけを 0 として扱います。
* 内訳(停止理由)は上位8項目を出し、残りは「その他(上位以外)」にまとめます。
