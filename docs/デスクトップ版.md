# デスクトップ版(Tauri)の作り

`全ライン グラフ分析.exe` は専用の窓で動き、**ポートを使いません**。予備としてブラウザ版
(`Start.vbs` / `start.bat`)も残してあります。2つは同時に動きません。
作りは python-web-tools / all-tools のデスクトップ版と同じ考え方です。

## 何が何をするか(各言語が得意なことをする)

```
全ライン グラフ分析.exe(Rust / Tauri)        … src-tauri/
 ├─ 窓(WebView2)・多重起動の防止・ブラウザ版との排他・閉じるときの確認
 ├─ Python を子として起動・見張り(起動できなければ理由の画面)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行の JSON + 本文)
        ▼
bridge.py(Python・標準ライブラリだけ)        … ポート無しの入口
 └─ graphapp.server.Exchange を呼ぶだけ(ブラウザ版と同じ振り分け)
        ▼
graphapp/(Python)                              … 集計CSV・式・保存・設定・配布設定・ログ(変えていない)
graphapp/static(JS)                            … 画面(確かめ・名前の入力は画面の中の窓 ui.js)
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・多重起動と排他・Python の見張り | OS の窓とプロセスを扱うのが得意。exe 1つで配れる |
| **Python**: 集計CSVを読む・稼働率と生産性の式・保存・設定 | 重い処理が無い(5ライン×半年で 0.2 秒)。式が all-tools と一致することを試験が守っている。書き直す利点が無く、危険だけがある。予備のブラウザ版も同じ処理を使う |
| **JS**: 画面の操作 | 今までどおり。デスクトップ版の窓では `confirm()`/`prompt()` に頼らず、画面の中の窓(`ui.js`)を使う |

## ポートを使わない仕組み

- 画面は独自の宛先 `app://localhost/`(Windows の WebView2 では `http://app.localhost/`)を読む。ネットワークを通らない
- 外枠はその要求を Python の標準入力へ渡し、標準出力から応答を受け取る(`src-tauri/src/bridge.rs` と `bridge.py`)
- 振り分けはブラウザ版と同じ `Exchange`。通り道(`transport`)で受ける Host / Origin を分けている
- 試験:
  - `tests/test_desktop.py`: **ソケットを作ると落ちる**ようにして bridge.py を動かしても、画面・API が通る
  - `scripts/desktop_smoke.py`: exe を本当に起動し、exe とその子(WebView)・Python の**どれも待ち受けていない**

## ブラウザ版とデスクトップ版は同時に動きません(どちらを後から開いても止まります)

| 先に動いているもの | 後から開いたもの | 動き |
|---|---|---|
| ブラウザ版 | 全ライン グラフ分析.exe | 「ブラウザ版が動いています」と出して閉じる |
| 全ライン グラフ分析.exe | ブラウザ版(Start.vbs / start.bat) | 「デスクトップ版が動いています」と出して止まり、窓を前に出す |
| 全ライン グラフ分析.exe | 全ライン グラフ分析.exe | 開かず、開いている窓を前に出す |
| ブラウザ版 | ブラウザ版 | もう1つは起こさず、動いている画面をブラウザで開く |

錠は **OS の名前付きの錠**(Windows のミューテックス `Local\all-lines-graph-analysis.instance` ほか)。
Microsoft Store 版の Python はファイルの置き場所を振り替えるので、ファイルの錠では exe から見えないため。
Python(`graphapp/instance_guard.py`、ctypes)と Rust(`src-tauri/src/instance.rs`)で同じ名前・同じ手順。
名前は試験で突き合わせている。

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓が出て、Python が準備できたらダッシュボード |
| 窓の × | 保存していない変更があれば「保存せずに終了しますか？」(画面が答えなければ 2.5 秒で閉じる) |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方・start.bat で経過を見る・記録の場所)を窓に出す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない) |
| 印刷・PDF / CSV・画像 | 今までどおり(CSV・画像は設定の書き出し先へ。ダウンロードは使わない) |

Python は**同梱しません**。各PCの Python を使います(`ALG_PYTHON` → `python.exe` → `py.exe -3`)。
追加ライブラリは要りません。

## 作り方・配り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。
Python の試験(Windows)→ Rust の試験 → exe の作成 → exe を起動しての確認、まで流れ、
成果物 `AllLinesGraph-windows` に `AllLinesGraph.exe` が入ります。

配るとき: `AllLinesGraph.exe` を **`Start.vbs` と同じフォルダ**に `全ライン グラフ分析.exe` の名前で置く
(`bridge.py` を同じフォルダか上の階層で探します。`ALG_ROOT` で指定も可)。

手元(Linux)で作るとき:

```
sudo apt-get install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev xvfb
cd src-tauri && cargo build && cargo test
xvfb-run python3 scripts/desktop_smoke.py --exe src-tauri/target/debug/AllLinesGraph
```

- 版は `graphapp/app_config.py`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- アイコンは `python scripts/make_desktop_icon.py`(標準ライブラリだけで作る)

## 確かめきれていないこと(Windows の実機で人が見る)

Linux(WebKitGTK)の上で窓を実際に動かして確かめました。Windows では GitHub Actions が
「起動して画面が届く・待ち受けない・2つ目は開かない・ブラウザ版は止まる・止めたら Python も終わる」まで確かめます。
次は実機で人が見る必要があります:

- 窓の × で、保存していない変更があるときの確認
- 「印刷・PDF」から実際に紙・PDF が出ること(WebView2 の印刷ダイアログ)
- Microsoft Store 版の Python で、ブラウザ版とデスクトップ版の排他が効くこと
- 「フォルダを選ぶ…」は今までどおりアプリの中の窓です(Windows のフォルダ選択の窓はまだ使っていません)
